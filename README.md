# Elevation Athletics React Theme

A WordPress theme that renders the Elevation Athletics site through a React app
built with Vite and powered by the design system component bundle.
WordPress owns routing, pages, menus, images, and form storage; React renders the
page UI.

---

## The 30-second mental model

```
Browser requests a URL
   │
   ▼
WordPress picks a PHP template          front-page.php / page.php / index.php
   │  prints the page slug onto the mount element:
   │      <main id="ea-react-root" data-page="about">
   ▼
assets/js/main.js  (the built bundle)   ← compiled from src/main.jsx by Vite
   │  reads data-page, looks it up in the PAGES map
   ▼
React renders the matching page          src/pages/HomePage.jsx, AboutPage.jsx, …
   wrapped in <Layout> (shared nav + footer from src/lib/shared.jsx)
   using EA Design System components      window.ElevationAthleticsDesignSystem_58666d
```

One built `main.js` serves **every** page. The slug decides which component renders.

> **Golden rule:** the browser runs the *built* `assets/js/main.js`, never the
> `.jsx` source. After editing anything in `src/`, run `npm run build` and
> hard-refresh (Ctrl/Cmd+Shift+R).

## Setting it up in Local (WP Local) to test

These steps assume you're using [Local](https://localwp.com/) (the "WP Local" app),
which is how this theme is developed.

### 1. Make sure the theme is in the right place

The theme lives at:

```
<Local site>/app/public/wp-content/themes/ea-react-theme
```

If you're copying it into a fresh site, drop the whole `ea-react-theme` folder
there.

### 2. Build the React bundle

You need [Node.js](https://nodejs.org/) installed (any current LTS). Open a
terminal **in the theme folder** and run:

```bash
cd "wp-content/themes/ea-react-theme"
npm install      # first time only — installs Vite + React (dev deps)
npm run build    # compiles src/ → assets/js/main.js
```

If `assets/js/main.js` exists afterward, the build worked. The theme will not
render the app without this file (see `ea_react_enqueue_assets()` in
[functions.php](functions.php) — it bails if `main.js` is missing).

### 3. Activate the theme

In **wp-admin → Appearance → Themes**, activate **Elevation Athletics React
Theme**.

### 4. Visit the site

Open the site (Local's **Open site** button, e.g. `http://elevation-athletics.local`).
The home page should render the badminton landing page.

### 5. Testing the Free Trial form locally

The Free Trial form emails the site admin. Local catches outgoing mail with
**Mailpit** — no real SMTP needed:

1. Submit the form on the home page.
2. In Local, open your site → **Tools → Open Mailpit**.
3. You'll see the "New free trial registration" email.
4. Every submission is also stored: **wp-admin → Free Trials** lists them with
   name, email, session, and date. (That admin screen is read-only — entries
   only arrive through the form.)

### Day-to-day dev loop

```bash
npm run build     # rebuild after editing src/
# then hard-refresh the browser (Ctrl/Cmd+Shift+R)
```

- `npm run dev` runs Vite's standalone preview server, but it is **not**
  WP-integrated (no WordPress data, menus, or REST endpoint). For real testing,
  always `npm run build` and view through Local.
- There's no watch/HMR wired into WordPress — the workflow is edit → build →
  refresh.

## Packaging the theme for upload

To install/update the theme on another WordPress site (**Appearance → Themes →
Add New → Upload Theme**), package it into a zip:

```bash
npm run zip       # deletes the old zip, then repackages this folder
npm run release   # runs `npm run build` first, then zips (fresh compiled JS)
```

Use **`npm run release`** most of the time so the upload always has an up-to-date
`assets/js/main.js`.

- The zip is written **one level up** at `wp-content/themes/ea-react-theme.zip`,
  with the theme nested under a top-level `ea-react-theme/` folder (what WordPress
  expects).
- Dev-only files (`node_modules`, `.git`, `.vscode`, the script itself) are
  excluded. Add more names to the `$exclude` array in
  [zip-theme.ps1](zip-theme.ps1) to trim the package further.
- Runs on Windows via PowerShell's built-in `Compress-Archive` — no extra tools.

## How routing works

WordPress decides the URL; React renders the matching component.

1. A visitor opens a URL. WordPress picks a PHP template
   ([front-page.php](front-page.php) for the home page, [page.php](page.php) for
   any Page, [index.php](index.php) as fallback).
2. The template prints the page's slug onto the mount element:
   `<main id="ea-react-root" data-page="about">`.
3. [src/main.jsx](src/main.jsx) reads `data-page` and renders the component
   registered for that slug in its `PAGES` map. Unknown slugs fall back to the
   home page.

```jsx
const PAGES = {
  home:  HomePage,
  about: AboutPage,
};
const slug = el.dataset.page || 'home';
const Page = PAGES[slug] || HomePage;   // unknown slug → home page
```

## Adding a new page

Example: adding a **Programs** page at `/programs/`.

1. **Create the component.** Copy [src/pages/AboutPage.jsx](src/pages/AboutPage.jsx)
   to `src/pages/ProgramsPage.jsx`, rename the component, edit the content. Wrap it
   in `<Layout>…</Layout>` so it gets the shared nav + footer.

2. **Register the slug.** In [src/main.jsx](src/main.jsx), import it and add it to
   `PAGES`. The key must match the WordPress page slug exactly:
   ```jsx
   import ProgramsPage from './pages/ProgramsPage.jsx';

   const PAGES = {
     home:     HomePage,
     about:    AboutPage,
     programs: ProgramsPage,   // ← new
   };
   ```

3. **Build:** `npm run build`.

4. **Create the WordPress Page.** wp-admin → **Pages → Add New**, set the title
   ("Programs"), confirm the **slug is `programs`** (the Permalink box under the
   title), and **Publish**.

5. **Visit `/programs/`.** The template hands `data-page="programs"` to React and
   `ProgramsPage` renders. (If the slug has no matching component, the home page
   shows — double-check the slug matches the `PAGES` key.)

6. **Add it to the menu (optional).** Appearance → **Menus**, add the page, and
   assign that menu to the **Primary Menu** location. The nav reads the Primary
   Menu automatically; until one is assigned it shows default example links.

## The shared Layout, nav, and footer

Everything common lives in [src/lib/shared.jsx](src/lib/shared.jsx):

- **`<Layout>`** — the page shell: `NavSection` + your page content + `PageFooter`.
- **`NavSection`** — a custom header (not the DS `NavBar`) so it can do dropdown
  submenus, a mobile hamburger menu, and the admin-swappable logo. It builds its
  link tree from the WordPress **Primary Menu**; with no menu assigned it falls
  back to a small example tree. It's `position: sticky` with a fixed per-breakpoint
  height (`NAV_HEIGHT`), and **collapses to the hamburger below `NAV_COLLAPSE_WIDTH`
  (1024px)** — a wider breakpoint than the page's 768px mobile layout, so the full
  nav never gets squished on tablet widths.
- **`PageFooter`** — logo, contact, socials, and two link columns. The **Quick
  Links**, **More Sports**, and **Contact** groups are driven by WordPress menus
  (Appearance → Menus) with hardcoded fallbacks; the **social icons** come from the
  Customizer (EA Social Links). The copyright line moves below everything on mobile.
- **`useViewport()`** — `{ isMobile, isTablet, width }`, breakpoints at 768/1024.
- **`useDSComponents()`** — returns the DS component bundle, polling briefly in
  case it loads just after React.
- **`getThemeData()`** — reads `window.eaReactData` (see below).
- **`Placeholder` / `MediaSlot`** — image helpers that degrade to a coloured block
  so the layout never breaks when an image isn't set.

### `window.eaReactData` (the bridge from WordPress to React)

`wp_localize_script` in [functions.php](functions.php) exposes server data to the
app. `getThemeData()` reads it:

| Field      | What it is |
|------------|------------|
| `siteUrl`  | Site base URL |
| `themeUrl` | Theme folder URL (used by `t.asset('file.png')` for bundled images) |
| `apiUrl`   | REST base, e.g. `http://site.local/wp-json/` |
| `nonce`    | `X-WP-Nonce` for authenticated REST calls |
| `images`   | Admin-uploaded image URLs from the Customizer (**EA Images**) |
| `texts`    | Editable copy strings from the Customizer (**EA Text**) — see below |
| `options`  | Layout toggles from the Customizer (**EA Options**): `useCarousel` (bool), `sports` (array of sport codes) |
| `social`   | Social profile URLs from the Customizer (**EA Social Links**): `instagram`, `facebook` |
| `menus`    | Menu trees from Appearance → Menus: `primary`, plus footer columns `footerQuickLinks`, `footerMoreSports`, `footerContact` |

## Editing images through wp-admin

All swappable images live in **Appearance → Customize → EA Images**. Upload and
**Publish**; leave a field blank to keep the theme's bundled default.

How it works:

- Each Customizer control stores an image URL as a WordPress *theme mod*
  (`ea_react_image_fields()` / `ea_customize_images()` in [functions.php](functions.php)).
- `ea_react_images()` collects them and `wp_localize_script` exposes them as
  `window.eaReactData.images`.
- React reads them via `getThemeData().images.*`. `MediaSlot` shows the uploaded
  image when set, or the original coloured placeholder when not.

**To add a new editable image:**

1. Add a field to `ea_react_image_fields()` in [functions.php](functions.php),
   e.g. `'ea_img_team' => array( 'key' => 'team', 'label' => 'Team photo' )`.
   It's registered in the Customizer and exposed to React automatically.
2. Use it in a component (where `const t = getThemeData()`):
   `<MediaSlot url={t.images.team} color="#D0F5FF" ratio="16/9" />`
   or `<img src={t.images.team || t.asset('team.png')} />`.
3. `npm run build`.

### Bundled default images

Defaults ship in `assets/images/` (logo, hero, social icons, etc.). Replacing a
file there changes the default for anyone who hasn't set a Customizer override.
Keep filenames lowercase, no spaces.

## Editing text through wp-admin

Nearly all on-page copy (headings, subtext, buttons, form labels, footer
headings, …) is editable under **Appearance → Customize → EA Text**. Fields are
grouped and labelled by section (`Hero — Heading`, `Footer — Copyright`, etc.).
Each field ships with its current copy as the default; **clear a field to restore
that default** (React also keeps the same string as a final fallback, so nothing
renders blank).

How it works (mirrors the images pipeline):

- `ea_react_text_fields()` / `ea_customize_texts()` in [functions.php](functions.php)
  register the controls (single-line `text` or multi-line `textarea`).
- `ea_react_texts()` collects them into `window.eaReactData.texts`.
- React reads them via `getThemeData().texts.<key>`, e.g.
  `t.texts.heroHeading || 'Play pickleball in Ontario'`.

**To add a new editable string:** add an entry to `ea_react_text_fields()` with a
unique setting slug, a `key`, a `label`, a `type` (`text`/`textarea`), and a
`default`; then read `t.texts.<key>` in the component with the same string as an
inline fallback; then `npm run build`.

One special field: **Free Trial — Session options** is a textarea, one session per
line — those lines become the "Choose Session" dropdown options.

## Layout options (EA Options)

**Appearance → Customize → EA Options** holds behaviour toggles, exposed as
`window.eaReactData.options`:

- **Show photo carousel** (`useCarousel`, default on) — when on, the section under
  the hero is a photo carousel (`NewProgramsSection`); when off, it's the **Free
  Trial** registration form (`FreeTrialSection`). Same slot, swapped by the toggle.
- **Active Programs sports** (`sports`) — a multi-select of the sports present in
  the live feed (Pickleball / Badminton / Basketball / Sports Camp). Filters which
  programs appear in the homepage Active Programs section. Implemented with a small custom
  `EA_Multi_Select_Control`.
- **League Hub sports** (`leagueHubSports`) — a separate multi-select for the
  League Hub / View All Programs template. If it has not been saved yet, the
  frontend falls back to the Active Programs sport selection.

## Social links (EA Social Links)

**Appearance → Customize → EA Social Links** — plain URL fields for the footer
social icons (Instagram, Facebook), exposed as `window.eaReactData.social`. **No
WordPress menu required.** Clear a field to hide that icon; clear all and the whole
"Follow us on our socials!" block disappears.

## Live "Active Programs" feed

The Active Programs section is data-driven from a public JSON feed
(`PROGRAMS_DATA_URL` in [src/pages/HomePage.jsx](src/pages/HomePage.jsx)):

1. `useProgramsFeed()` fetches the rows once on mount (client-side, cache-busted).
2. `buildProgramList(rows, sports, userCoords)` keeps only active EA/TS rows whose
   sport is selected (EA Options), then renders **individual program registration
   cards** instead of collapsing rows into one card per city.
3. Cards are capped at `PROGRAMS_LIMIT` (3) and each Register/Join Waitlist button
   links directly to the row's `RegisterLink`.
4. Programs sort by registration priority: starting soon + enrollment open + not
   full, then in-progress open programs, then waitlist/full and enrollment-closed
   variants. If every program is already in progress, the open non-full programs
   with the furthest end date sort first so late joiners see the best options.
5. **"Programs Near Me"** asks for the visitor's location via the browser
   Geolocation API and re-sorts the cards nearest-first using a hardcoded
   `CITY_COORDS` table + Haversine distance. Requires **HTTPS**; on failure it
   falls back to the default priority order.

If the fetch fails or returns nothing, the section falls back to the bundled
program cards, so it never renders empty. New cities in the feed need a
`CITY_COORDS` entry to participate in the nearest-first sort.

## The Free Trial form (React ↔ WordPress REST)

The home page's Free Trial form (`FreeTrialSection` in
[src/pages/HomePage.jsx](src/pages/HomePage.jsx)) POSTs to a custom REST endpoint:

```
POST  {apiUrl}ea/v1/free-trial
headers: { Content-Type: application/json, X-WP-Nonce: <nonce> }
body:    { name, email, session, website }   // `website` is a spam honeypot
```

Server side (in [functions.php](functions.php)):

1. `ea_handle_free_trial()` validates input (and silently drops bots that fill the
   `website` honeypot).
2. It stores the submission as a private **`ea_free_trial`** post (the record of
   truth), viewable under **wp-admin → Free Trials**.
3. It emails the site admin (`admin_email`) as a best-effort notification — locally
   caught by **Mailpit** (Local → Tools → Open Mailpit).

The `ea_free_trial` post type is admin-only (`'create_posts' => 'do_not_allow'`),
so entries only ever come from the form.

Admins can download the saved registrations from **wp-admin → Free Trials** using
the **Export Free Trials CSV** button above the list table. The CSV includes the
submission ID, athlete name, email, city, sport, selected session, and submitted
date. Free Trial rows currently export as city `Newmarket` and sport `Badminton`
so they line up with newsletter signups.

## The Newsletter signup (React ↔ WordPress REST)

Works like the Free Trial form, with **per-location** tracking:

```
POST  {apiUrl}ea/v1/newsletter
body: { email, location, sport, website }   // `location`/`sport` optional; `website` is a honeypot
```

Server side (in [functions.php](functions.php)):

1. `ea_handle_newsletter()` validates the email and keeps **one `ea_newsletter`
   record per email** (deduped by address).
2. If a `location` is provided, it's added to that subscriber's `_ea_locations`
   set (so one email can be subscribed to several locations).
3. It emails the admin (best-effort → Mailpit locally).

Subscribers are listed under **wp-admin → Newsletter**, with **Email**, **City**,
**Sport**, and **Subscribed** columns.

Admins can download the saved subscribers from **wp-admin → Newsletter** using
the **Export Newsletter CSV** button above the list table. The CSV includes the
subscriber ID, email, city, sport, and subscribed date. The default sport, region
and city come from `EA_CC_DEFAULT_SPORT`, `EA_CC_DEFAULT_REGION` and
`EA_CC_DEFAULT_CITY` in `wp-config.php` (old names kept so existing configs work).

After saving, each signup is sent to the **EA Operations app** — one signed
request per city, with the signup's sport — by [inc/ea-app-sync.php](inc/ea-app-sync.php).
Status, backfill and the site secret live under **Settings → EA App Sync**.
Constant Contact is no longer used; its integration has been removed.

Two entry points on the home page:

- **Newsletter section** (bottom) — general signup (no location).
- **Location card "Subscribe" button** — opens a **popup** (`NewsletterModal`)
  pre-tagged with that card's location; enter email → confirmation, all in place.

## How the assets load

```
WordPress page load
  ├── wp_head()
  │   ├── ea_ds/tokens/fonts.css       ← BBH Bogle + Inclusive Sans @font-face
  │   ├── ea_ds/tokens/colors.css      ← --ea-* colour variables
  │   ├── ea_ds/tokens/typography.css  ← --font-display, --font-body, scale vars
  │   ├── ea_ds/tokens/spacing.css     ← --space-*, --radius-*, --shadow-*
  │   ├── ea_ds/tokens/base.css        ← reset + body defaults
  │   └── style.css                    ← theme stylesheet
  │
  └── wp_footer()
      ├── react@18.3.1      (unpkg CDN UMD)  → window.React
      ├── react-dom@18.3.1  (unpkg CDN UMD)  → window.ReactDOM
      ├── ea_ds/_ds_bundle.js                → window.ElevationAthleticsDesignSystem_58666d
      │     exports: NavBar, Button, Card, SectionHeading, LocationCard,
      │              FaqItem, NewsletterForm, Badge, Input, Carousel, Logo
      └── assets/js/main.js (Vite IIFE build)
            renders the page component for data-page into #ea-react-root
            + reads window.eaReactData
              (siteUrl, themeUrl, apiUrl, nonce, images, texts, options, social, menus)
```

### Why the build is an IIFE, not an ES module

WordPress loads React/ReactDOM as **UMD globals** from a CDN. An ESM bundle would
emit bare `import ... from "react"`, which the browser can't resolve without an
import map → blank page. So [vite.config.js](vite.config.js) outputs **IIFE**
format, marks `react`/`react-dom` as external, and maps them to `window.React` /
`window.ReactDOM`. The result is a plain `<script>` (no `type="module"` needed)
that loads after React and the DS bundle.

## Troubleshooting

| Symptom | Likely cause / fix |
|---|---|
| Blank page, no content | `assets/js/main.js` missing → run `npm run build`. |
| Edits don't show up | You didn't rebuild, or didn't hard-refresh. `npm run build` + Ctrl/Cmd+Shift+R. |
| Nav shows example links | No menu assigned to the **Primary Menu** location (Appearance → Menus). |
| Page renders the home page instead | The WP page slug doesn't match a `PAGES` key in [src/main.jsx](src/main.jsx). |
| Free Trial email not arriving | Check Local → Tools → **Open Mailpit**; the entry is still saved under **Free Trials** regardless. |
| Components look unstyled briefly | DS bundle loads just after React; `useDSComponents()` polls and re-renders. Falls back to `FB.*` styles until then. |
| Edited copy not changing | Confirm you edited the right field in **Customize → EA Text** and clicked **Publish** (transport is `refresh`, so the preview reloads). |
| "Locations Near Me" does nothing | Geolocation needs **HTTPS** and permission; on plain `http://` it silently falls back to the default order. |
| Homepage program cards empty / wrong sport | Check **Customize → EA Options → Active Programs sports**, and that the JSON feed is reachable. |
| League Hub cards empty / wrong sport | Check **Customize → EA Options → League Hub sports**, and that the JSON feed is reachable. |
| Nav squished on tablet | It collapses to the hamburger below 1024px (`NAV_COLLAPSE_WIDTH` in `shared.jsx`) — raise it if needed. |
